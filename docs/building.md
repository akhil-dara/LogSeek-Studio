# Building LogSeek Studio yourself

You do not need to build LogSeek Studio to use it: the [Releases page](https://github.com/akhil-dara/LogSeek-Studio/releases) has an installer and a portable zip. Build it yourself when you want to check what you run, change it, or try the newest source.

## What you need

- Windows 10 or 11, 64-bit.
- [Git](https://git-scm.com/download/win).
- The stable Rust toolchain, installed with [rustup](https://rustup.rs). Rustup asks for the Visual Studio C++ build tools if they are missing; accept that.
- About 6 GB of free disk space for the build folder.
- Only for the installer: [Inno Setup 6](https://jrsoftware.org/isinfo.php).

## Get the source

```powershell
git clone https://github.com/akhil-dara/LogSeek-Studio.git
```

```powershell
cd LogSeek-Studio
```

## Build the program

```powershell
cargo build --release -p logseek
```

The first build downloads the libraries it uses and takes several minutes. The result is one file, `target\release\logseek.exe`. It needs nothing beside it: copy it anywhere and run it.

## Run the tests

```powershell
cargo test --workspace
```

Every test should pass. The tests make their own small files; they need no sample data and no network.

## Build the installer

Build the program first, then:

```powershell
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" "/DAppVersion=0.1.0" installer\logseek.iss
```

If Inno Setup was installed for all users, `ISCC.exe` is in `C:\Program Files (x86)\Inno Setup 6` instead. The installer is written to `dist\LogSeek-Studio-0.1.0-setup.exe`. It installs for the current account without administrator rights, or for all users when that is chosen on its first page.

## How the project is laid out

| Folder | What it holds |
| --- | --- |
| `crates/logseek-core` | The engine: reading files, the index, search, formulas, the analysis tools. It has no interface code. |
| `crates/logseek` | The desktop app: the window, the grid, the panels, export. |
| `assets/brand` | The icon. |
| `installer` | The Inno Setup script. |
| `licenses` | The licences of the libraries built into the program (generated by `tools/third_party_licenses.py`). |
| `tools` | Maintenance scripts. |
| `docs` | These pages. |
| `.github/workflows` | The release build. |

## The developer build

```powershell
cargo build --release -p logseek --features devtools
```

This build also reads a set of `LOGSEEK_*` environment variables that drive the app without a person: they take a screenshot after a number of frames, run a timed sequence of actions, or open a view directly. They exist for testing. The normal build ignores them all, so nothing in the environment can steer the program people download.

## How releases are made

Pushing a version tag such as `v0.1.0` starts `.github/workflows/release.yml` on GitHub. It runs the tests, builds the program, makes the portable zip and the installer, writes `SHA256SUMS.txt`, and attaches all three to a release.

To check a download against the list:

```powershell
Get-FileHash .\LogSeek-Studio-0.1.0-setup.exe -Algorithm SHA256
```

The value shown must match the line for that file in `SHA256SUMS.txt`.
